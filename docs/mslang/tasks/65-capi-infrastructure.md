# C API 基础设施（cbindgen + 手写类型头文件 + 构建集成）

## 所属阶段
Phase 6 — 模块系统 + 标准库

## 前置任务
Phase 1-6 全部已完成任务（特别是 52-gc、45-module-system、46-49 stdlib 注册模式、25-builtins-basic NativeFunction 约定）

## 目标
搭建 C API 基础设施：cbindgen 配置、手写 types.h 核心类型定义、umbrella 头文件 mslang.h、build.rs 集成、Rust 侧 `src/capi/` 模块框架。所有后续 C API 任务（66-74）依赖本任务。

## 设计规格

参照 [13-capi](../13-capi.md) § 头文件结构、§ 版本宏、§ 平台兼容性宏、§ types.h 核心类型：

### 头文件结构

```
include/mslang/
├── mslang.h              // umbrella，include 全部子头文件
├── types.h               // 手写：核心类型定义、枚举、宏、版本号
├── vm.h                  // cbindgen 生成（Task 67）
├── value.h               // cbindgen 生成（Task 68）
├── call.h                // cbindgen 生成（Task 69）
├── error.h               // cbindgen 生成（Task 70）
├── module.h              // cbindgen 生成（Task 71）
├── class.h               // cbindgen 生成（Task 72）
└── gc.h                  // cbindgen 生成（Task 74）— L4 见下方注
```

> **gc.h 差异说明**（L4）：`13-capi.md:22-32` 的头文件结构列 6 个文件（vm/value/call/error/module/class），**无 gc.h**。GC 交互函数（`msRoot`/`msUnroot`/`msGcCollect`/`msGcStats` 等）在 13-capi.md 中分散在 value.h 和 vm.h 段。本任务新增独立的 `gc.h`（cbindgen 从 `src/capi/gc.rs` 生成），将 GC 交互函数集中管理——这是对 13-capi.md 头文件结构的**设计改进**，使 GC API 更内聚。task 74 实现时将 GC 函数放入 `src/capi/gc.rs` 而非 `src/capi/value.rs`。

### 职责划分

| 文件 | 生成方式 | 内容 |
|---|---|---|
| types.h | **手写** | 版本宏、平台宏、不透明类型、函数指针类型、枚举、布尔常量 |
| mslang.h | **手写** | umbrella 头文件，include types.h |
| vm.h ~ class.h | **cbindgen** | 从 `src/capi/*.rs` 的 `#[no_mangle] pub extern "C"` 函数自动生成 |

## 实现细节

### 1. cbindgen 配置 — cbindgen.toml

项目根目录下创建 `cbindgen.toml`：

```toml
language = "C"
include_guard = "MSLANG_GENERATED_H"
autogen_warning = "/* Warning: this file is auto-generated by cbindgen. Do not modify manually. */"
tab_width = 4
style = "tag"
include_version = true

[defines]
"feature = capi" = "MS_CAPI_ENABLED"

[export]
include = [
    "MsStatus",
    "MsType",
    "MsGcType",
    "MsFutureState",
]

[fn]
prefix = "MS_API"

[struct]
rename_fields = "SnakeCase"

[enum]
prefix_with_name = true
rename_variants = "ScreamingSnakeCase"

[parse]
parse_deps = false
include = ["mslang"]

[parse.expand]
crates = ["mslang"]
features = ["capi"]
```

> **include_guard 选为 `MSLANG_GENERATED_H`**（M4）：手写 mslang.h 用 `MSLANG_H` guard。若 cbindgen 生成的头文件也用 `MSLANG_H`，include 了生成的 vm.h 后 mslang.h 的 guard 已定义，导致 types.h 被跳过。故生成文件用不同 guard。
>
> **cbindgen 版本**（R3）：`cbindgen = "0.26"`。cbindgen 的 Builder API 在小版本间可能有变化，如遇 `with_src`/`with_config` 语义差异，锁定 patch 版本 `=0.26.0`。

### 2. Cargo.toml 变更

在现有 `Cargo.toml`（含 `description`、`clap`/`thiserror` 依赖、`[[bin]]` 段）基础上**追加**以下段：

```toml
# ── 以下为新增段，追加到现有 Cargo.toml ──

[features]
capi = []

[lib]
crate-type = ["cdylib", "rlib"]

[build-dependencies]
cbindgen = "0.26"
```

- `capi` feature：条件编译 C API 模块，不影响默认构建
- `cdylib`：生成 C 动态链接库（`.dll` / `.so` / `.dylib`）
- `rlib`：保留普通 Rust 库构建
- `cbindgen` build-dependency：`build.rs` 中调用，从 Rust 源码生成 C 头文件

### 3. build.rs

项目根目录下创建 `build.rs`：

```rust
fn main() {
    #[cfg(feature = "capi")]
    {
        let crate_dir = std::env::var("CARGO_MANIFEST_DIR").unwrap();
        let config = cbindgen::Config::from_file("cbindgen.toml")
            .expect("Unable to read cbindgen.toml");

        let bindings = cbindgen::Builder::new()
            .with_crate(&crate_dir)
            .with_config(config.clone())
            .generate();

        match bindings {
            Ok(_bindings) => {
                let include_dir = std::path::Path::new("include/mslang");
                // V2: create_dir_all 失败应 panic 而非静默忽略。
                std::fs::create_dir_all(include_dir)
                    .expect("cannot create include/mslang directory");

                let hand_written = ["types.h", "mslang.h"];

                let modules = [
                    ("vm", "vm.h"),
                    ("value", "value.h"),
                    ("call", "call.h"),
                    ("error", "error.h"),
                    ("module", "module.h"),
                    ("class", "class.h"),
                    ("gc", "gc.h"),
                ];

                for (module_name, filename) in &modules {
                    let mut builder = cbindgen::Builder::new()
                        .with_crate(&crate_dir)
                        .with_config(config.clone());

                    // V3: 使用绝对路径（基于 crate_dir），避免 CWD 依赖。
                    let src_path = std::path::Path::new(&crate_dir)
                        .join(format!("src/capi/{}.rs", module_name));
                    builder = builder.with_src(src_path.to_str().unwrap());

                    if let Ok(module_bindings) = builder.generate() {
                        let out_path = include_dir.join(filename);
                        if !hand_written.contains(&filename.as_str()) {
                            module_bindings.write_to_file(&out_path);
                        }
                    }
                }
            }
            Err(e) => {
                // R1: cbindgen 失败时 panic（而非静默降级），使 CI 立即暴露问题。
                panic!("cbindgen failed: {}", e);
            }
        }
    }
}
```

行为：
- 仅在 `--features capi` 时执行 cbindgen 生成
- 不覆盖手写文件（types.h、mslang.h）
- cbindgen 不可用时打印警告，不中断构建
- 从 `src/capi/` 各子模块生成对应头文件

### 4. include/mslang/types.h（手写）

```c
#ifndef MS_TYPES_H
#define MS_TYPES_H

#include <stdint.h>
#include <stddef.h>

/* ── Version ── */

#define MS_VERSION_MAJOR  0
#define MS_VERSION_MINOR  1
#define MS_VERSION_PATCH  0
#define MS_VERSION        "0.1.0"

#define MS_VERSION_AT_LEAST(major, minor, patch)              \
    (MS_VERSION_MAJOR > (major) ||                             \
     (MS_VERSION_MAJOR == (major) && MS_VERSION_MINOR > (minor)) || \
     (MS_VERSION_MAJOR == (major) && MS_VERSION_MINOR == (minor) && \
      MS_VERSION_PATCH >= (patch)))

/* ── Platform macros ── */

/* R2: MS_BUILDING 仅在构建 mslang.dll 自身时定义（由 Rust 侧 #[no_mangle]
 * pub extern "C" 自动处理 dllexport，不需 C 宏）。C 扩展模块编译时
 * **不定义** MS_BUILDING（使用 dllimport 链接 mslang.dll）。 */
#ifdef _WIN32
  #ifdef MS_BUILDING
    #define MS_API __declspec(dllexport)
  #else
    #define MS_API __declspec(dllimport)
  #endif
#else
  #define MS_API __attribute__((visibility("default")))
#endif

#ifdef _WIN32
  #define MS_MODULE_INIT __declspec(dllexport)
#else
  #define MS_MODULE_INIT __attribute__((visibility("default")))
#endif

/* ── Opaque types ── */

typedef struct MsVM MsVM;
typedef struct MsValue MsValue;

/* ── Function pointer types ── */

typedef MsValue* (*MsCFunction)(MsVM* vm, MsValue* const* args, int nargs);
typedef void (*MsAsyncFunction)(MsVM* vm, MsValue* const* args, int nargs,
    MsValue* future);
typedef void (*MsFinalizerFn)(MsVM* vm, MsValue* obj, void* userdata);
/* L1: MsWriteFn 用于 vm.h 的 msSetStdout/msSetStderr（13-capi.md:167）。
 * 提前在手写 types.h 定义，使 cbindgen 生成的 vm.h 可引用。 */
typedef int (*MsWriteFn)(const char* data, size_t len, void* userdata);

/* ── Enums ── */

/* V4 注意：MsType 与内部 TypeTag（14-gc.md:89-112）是不同枚举。
 * MsType 包含 Nil/Bool/Float 等内联类型，TypeTag 仅含堆类型（STRING=1, LIST=2, ...）。
 * 两者的数值不对应；转换映射由 task 67 的 msTypeof 实现中的 match 完成。 */
typedef enum MsType {
    MS_TYPE_NIL          = 0,
    MS_TYPE_BOOL         = 1,
    MS_TYPE_INT          = 2,
    MS_TYPE_FLOAT        = 3,
    MS_TYPE_STRING       = 4,
    MS_TYPE_LIST         = 5,
    MS_TYPE_DICT         = 6,
    MS_TYPE_TUPLE        = 7,
    MS_TYPE_SET          = 8,
    MS_TYPE_FUNCTION     = 9,
    MS_TYPE_CLASS        = 10,
    MS_TYPE_INSTANCE     = 11,
    MS_TYPE_MODULE       = 12,
    MS_TYPE_GENERATOR    = 13,
    MS_TYPE_FUTURE       = 14,
    MS_TYPE_CHANNEL      = 15,
    MS_TYPE_ITERATOR     = 16,
    MS_TYPE_BOUND_METHOD = 17,
    MS_TYPE_JOIN_HANDLE  = 18,
} MsType;

typedef enum MsStatus {
    MS_OK    =  0,
    MS_ERROR = -1,
    MS_YIELD =  1,
} MsStatus;

typedef enum MsGcType {
    MS_GC_MINOR = 0,
    MS_GC_MAJOR = 1,
    MS_GC_FULL  = 2,
} MsGcType;

typedef enum MsFutureState {
    MS_FUTURE_PENDING  = 0,
    MS_FUTURE_RESOLVED = 1,
    MS_FUTURE_REJECTED = 2,
} MsFutureState;

/* L5: MsFutureState 在 13-capi.md 中位于 call.h 段，本任务提前到手写 types.h，
 * 使 cbindgen 生成的 call.h 可引用此枚举（13-capi.md:433-437）。 */

/* L2: MsGcStats 用于 task 74 的 msGcStats 返回值（13-capi.md:678-687）。
 * 提前在手写 types.h 定义，避免 cbindgen 生成 gc.h 时的类型依赖缺失。 */
typedef struct MsGcStats {
    uint64_t minorGcCount;
    uint64_t majorGcCount;
    uint64_t totalPauseNs;
    uint64_t lastPauseNs;
    uint64_t youngSize;
    uint64_t oldSize;
    uint64_t losSize;
    uint64_t bytesFreed;
} MsGcStats;

/* L6: MsFuncDef/MsConstDef/MsModuleDef 结构体由 cbindgen 从 Rust #[repr(C)]
 * struct 生成（task 72 module.h），无需在此手写。 */

/* ── Boolean constants ── */

#define MS_TRUE  1
#define MS_FALSE 0

#endif /* MS_TYPES_H */
```

## 验证标准

1. `cargo build` 编译无错误（默认不启用 capi）
2. `cargo build --features capi` 编译无错误（启用 capi 模块框架）
3. `include/mslang/types.h` 是合法 C 头文件（包含守卫、宏定义、类型定义完整）
4. `include/mslang/mslang.h` 正确 include types.h
5. cbindgen 可正常运行，不报错（即使生成内容为空）
6. `cargo test --features capi` 通过
7. 最小 C 程序 `#include <mslang/mslang.h>` 可通过 C 编译器编译（`-I include`）
8. `src/capi/` 模块结构与 [12-implementation-plan](../12-implementation-plan.md) 一致
9. 不启用 `capi` feature 时，`src/capi/` 不参与编译
10. **R1 CI 检查**：`cargo build --features capi` 后验证 `include/mslang/vm.h`（及 value.h/call.h/error.h/module.h/class.h/gc.h）文件存在——cbindgen 失败时 build.rs panic 使构建中断，但 CI 应额外检查生成文件非空
